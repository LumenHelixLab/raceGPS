## Command used

This reuses World Environment's run-2 recipe (editor GUI + `-ExecCmds="py ..."`). The helper script lives outside the repo; a copy is in this folder as `CA-2026-10-05-capture-helper.py`.

```
"C:\Program Files\Epic Games\UE_5.7\Engine\Binaries\Win64\UnrealEditor.exe" "C:\projects\raceGPS-grokbot-cleveland\apps\unreal-akron-beta\raceGPSAkronBeta.uproject" /Game/Maps/Cleveland5_0KmWorld -d3d12 -log -NoSplash -ExecCmds="py C:/Users/cgp22/ca-stills-staging/_ca_ribbon_stills.py"
```

The helper does the following, in order:
1. Spawns a transient `ClevelandEnvironmentActor` (photo backdrop on, the same as WE) and runs `LoadAndBuild`.
2. Runs `ClevelandLookDirector.ApplyVisualMode` and `env.ApplyLookMode`.
3. Pilots a CameraActor and takes `HighResShot 1920x1080 filename=...`.
4. Calls `quit_editor()`.

Shots were taken first in Sunset (the LaunchCleveland.bat default) and then in Midnight (WE's preset). No exposure, material or UV overrides were used.

**Deviation from the brief:** I did not use `ClevelandShowcaseGameMode` + `CaptureHeroStill`. `CaptureHeroStill` is a protected C++ method, not a `UFUNCTION(Exec)`, so it can't be called from the console. Its only camera is the fixed intro/chase framing, which can't produce an overhead or a placed driver eye. No game mode override was needed because this was an editor-world render.

**Ribbon data note:** the EZ ribbon JSONs (`racing_line_ez.json`, `checkpoints_ez.json`) are **not on omni**. Only `metrics.json` and `ribbon_overlay.svg` are. The map renders the source Burke course (`citypacks/cleveland/burke_gp_1997`). The EZ line shares the source XODR, and the length difference is 6.8 m (3268.99 vs 3275.82 m, 410 samples). Cameras were placed from the source `racing_line.json`.

## Mirroring note

UE is left-handed. In Frame A (X = east, Y = north), the overhead camera at yaw 90 puts north at screen-top and **east at screen-left**. So the overhead is a horizontal mirror of a real-compass map: flip it left-right to compare with a normal map of Burke Lakefront. I judged the overhead against the ribbon sample data projected through the same camera, not against real-world map orientation. Also note that `ClevelandSoloGameMode` uses UE yaw = compass - 90, which only matches the true travel direction on axes where the mirroring is symmetric. For the driver camera I took yaw from consecutive line samples instead: atan2(dy, dx) = -157.8.
